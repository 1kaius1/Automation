# Changelog

All notable changes to `Proxmox-Forgejo/` are documented here. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed

- `docs/ANSIBLE_VAULT_GUIDE.md` **moved to `../Shared/Ansible/docs/`** — it's generic Vault instruction every project uses, not Forgejo-specific. All references here (`README.md`, `Install-Prerequisites.sh`, `deploy_forgejo.yaml`, `inventory/group_vars/forgejo/{vars.yaml,vars.yaml.example,vault.yaml.example}`) repointed. `docs/` keeps `reverse-proxy.nginx.conf.example`. (The §12 broadening — per-vault-file identity split, `vault_encrypt_id`, password-file placement — went with it; see `Shared/CHANGELOG.md`.)
- `Install-Prerequisites.sh`: the vault-password check now iterates **every** `label@path` entry in `vault_identity_list` (was only the first) and accepts an executable password *script*, not just a plain file — so a multi-identity / relocated-vault setup is verified properly.
- `Deploy.sh` / `Install-Prerequisites.sh` run Ansible from the repo-local venv (`<repo-root>/.venv`, built by `../Shared/Ansible/bootstrap.sh`) instead of a system / `~/.local` install, and install collections into `<repo-root>/.ansible/collections` — the system Python is left alone (installing `cryptography` there broke other distro apps). The stale `../Installers/Install-Ansible.sh` pointer is now `../Shared/Ansible/bootstrap.sh`.
- git-over-SSH is now proxied like the web port. `forgejo_ssh_port` (2222) is the in-VM listen port, restricted by `ufw` to `reverse_proxy_source_cidr` (was world-open); new `forgejo_ssh_public_port` (default = `forgejo_ssh_port`; example real value `10000`) is the reverse-proxy `stream {}` listen port and Forgejo's advertised `SSH_PORT` in clone URLs. `app.ini` renders `SSH_PORT`/`SSH_LISTEN_PORT` separately now. A high non-standard public port keeps git-SSH off the ports mass scanners hammer.
- **Vault files are no longer committed.** `inventory/group_vars/forgejo/vault.yaml` is now gitignored — the `$ANSIBLE_VAULT;1.2;AES256;<vault-id>` header is cleartext and the `<vault-id>` label names a real credential, so even ciphertext stays out of this public repo. Only `vault.yaml.example` is committed; you create the real file locally with the shared repo vault password, and back it up out of band (not recoverable from git). `README.md` and `docs/ANSIBLE_VAULT_GUIDE.md` (§1, §3, §11, §13) rewritten accordingly. Matches the same rule already applied to `../Shared/Ansible/group_vars/proxmox_cluster/vault.yaml`.
- **`ansible.cfg` now comes from one canonical example.** `Proxmox-Forgejo/ansible.cfg.example` removed; the real `ansible.cfg` is copied from `../Shared/Ansible/ansible.cfg.example` (the single repo-wide example: a `COMMON` section every project uses verbatim — including the one shared `vault_identity_list` — plus a per-project section). `Install-Prerequisites.sh` / `README.md` / `docs/ANSIBLE_VAULT_GUIDE.md` updated. Dropped the `callback_whitelist = timer, profile_tasks` line — those callbacks aren't bundled in ansible-core 2.21 and `ansible.posix` isn't installed, so it only produced a load warning.
- **Full adoption of the shared two-disk `/opt` layout.** `roles/forgejo_prereqs` + `roles/forgejo_install` defaults: the binary moves to `/opt/app/forgejo` (was `/usr/local/bin`); all state — `repositories/`, LFS, attachments, logs, and the `git` user's home — moves under `/opt/data/forgejo` (were `/var/lib/forgejo`, `/var/log/forgejo`, `/home/git`). `/etc/forgejo` (config) is unchanged. `forgejo_prereqs` gains one task creating `/opt/app/forgejo`; the systemd unit's `WorkingDirectory` / `ExecStart` / `ReadWritePaths` follow the vars with no template edit. `/opt` is inherited from the template (`full: true` clone) and is **not** resized during deploy.
- Corrected leftover `Create-Template.yaml` strings in this changelog's `### Removed` history to `create-template-linux.yaml` (that playbook's current name).
- `inventory/group_vars/proxmox_pve1/vars.yaml{,.example}`: `vm_template_name` is `T-Debian-13-Cloud` — the shared manifest's template names now carry a `-<Source>` segment (`Cloud` | `ISO`); copy a name verbatim from `../Shared/Ansible/template_manifest.yaml`.
- `README.md` / `Install-Prerequisites.sh` / `docs/ANSIBLE_VAULT_GUIDE.md`: the shared Proxmox credential is named `svc_ansible@pve` (was `ansible-automation@pve` — a stale name; the deployed token was already `svc_ansible@pve`), and the bootstrap step now runs `../Shared/Ansible/create-pve_svc_user.yaml` (the former `setup_proxmox_automation_account.yaml`, merged with the node-SSH-account setup). Forgejo's wiring was already correct (`deploy_forgejo.yaml` loads `../Shared/Ansible/group_vars/proxmox_cluster/`), so these are doc-only fixes.
- `inventory/group_vars/proxmox_pve1/vars.yaml{,.example}`: `vm_template_vmid` moved to the 90000 template band (`T-Debian-13` is now 90001) to follow the shared allocation in `../Shared/Ansible/template_manifest.yaml`, which is now the source of truth for the template `name → VMID` mapping. The surrounding comment points there instead of describing an ad-hoc "9000+" convention.
- `roles/proxmox_preflight`: the "template doesn't exist" failure message now gives the real build command (`ansible-playbook create-template-linux.yaml -e template_target=<name>`) and notes the name must be a manifest row. Stale `Create-Template.yaml` references updated to the current `create-template-linux.yaml` here and in `deploy_forgejo.yaml`.

### Added

- `docs/reverse-proxy.nginx.conf.example` — worked nginx config for the shared proxy that fronts Forgejo: the `map`, the HTTPS `server` (git-push body-size / timeout / forwarded-header tuning), and a top-level `stream {}` block forwarding `forgejo_ssh_public_port` → the VM's `forgejo_ssh_port`. `README.md` "Reverse proxy" links it.
- Initial project: Ansible-based Forgejo deployment on a Proxmox VM, provisioned entirely via Ansible (no Terraform/OpenTofu).
- `deploy_forgejo.yaml` — main playbook, fully non-interactive (no `vars_prompt`/`pause`).
- Roles: `proxmox_preflight`, `create_forgejo_vm` (clone + cloud-init), `forgejo_prereqs`, `forgejo_database` (PostgreSQL), `forgejo_install` (checksum-verified binary, systemd-hardened service, idempotent admin bootstrap), `forgejo_backup`, `forgejo_verify`.
- `backup_forgejo.yaml` — standalone on-demand backup playbook.
- Ansible Vault used for all secrets, `vars.yaml`/`vault.yaml` split. (The real `vault.yaml` is gitignored, not committed — see `### Changed`.)
- `docs/ANSIBLE_VAULT_GUIDE.md` — complete Ansible Vault walkthrough for a first-time user.
- `Deploy.sh` / `Install-Prerequisites.sh` convenience scripts.
- `.example` config files (`hosts.ini.example`, `group_vars/*/vars.yaml.example`, `group_vars/forgejo/vault.yaml.example`; `ansible.cfg` is copied from the repo-wide `../Shared/Ansible/ansible.cfg.example` — see `### Changed`) with the real, site-specific files gitignored — this repo is public, so real cluster/node names, domain, admin email, and any personalized vault-id label never get committed. `Install-Prerequisites.sh` reads the vault password path out of the real `ansible.cfg` rather than assuming a fixed filename, so a personalized label still works.
- `docs/ANSIBLE_VAULT_GUIDE.md`: a callout clarifying that `homelab`/`vault_pass_homelab.txt` throughout the guide are just the default example (matching `ansible.cfg.example`), not hardcoded anywhere in the playbooks.
- `forgejo_install`: `forgejo_version` now accepts either `"16.0.3"` or `"v16.0.3"` (normalized once via `forgejo_version_number`) — the download URL previously double-prepended `v` when the version was given with a leading `v`, producing a broken release URL.
- Disaster-recovery design: off-node backup storage treated as a stated prerequisite, since the environment's storage is local-only per node today — with an explicit `backup_storage_target: "none"` opt-out (`proxmox_preflight` downgrades the check to a loud warning instead of blocking the deploy) for testing before that storage exists.

### Removed

- Stray `temp.key` / `temp.key.pub` from the project root — an unreferenced `kaius@behemoth` ed25519 keypair, nothing used it.
- `roles/prepare_vm_template/` — VM template building isn't specific to Forgejo, so it moved to `../Shared/Ansible/create-template-linux.yaml`, usable by any project in this mono-repo. This project now only ever *clones* an existing template. `deploy_forgejo.yaml` no longer has a play targeting `proxmox_pve1` at all (nothing here needs direct SSH to the Proxmox node anymore — everything goes through the API), so `inventory/hosts.ini`'s `[proxmox_pve1]` SSH connection group was removed too. `inventory/group_vars/proxmox_pve1/vars.yaml` dropped `cloud_image_url`/`cloud_image_checksum_url` (moved with the template logic) but keeps `vm_template_name`/`vm_template_vmid`, since this project still needs to know which template to clone from. `proxmox_preflight` gained a check that the configured template actually exists and is a template, failing with a message pointing at `create-template-linux.yaml` if not — this project has no way to build one itself anymore, so that gap needed to be caught explicitly rather than surfacing as a confusing clone failure later.

### Fixed

- `roles/proxmox_preflight` now fails fast if `forgejo_admin_username` is one of Forgejo's reserved names (`admin`, `api`, `login`, `explore`, …) — `forgejo admin user create --username admin` fails deep into `forgejo_install` with an opaque `CreateUser: name is reserved [name: admin]`, well after the VM is already built. The list is a common-collision subset, not exhaustive; Forgejo's own list is authoritative.
- `create_forgejo_vm` never set the clone's network. The shared template is built with its NIC on the build VLAN, so every Forgejo VM came up on that bridge (`network_bridge` from `proxmox_pve1/vars.yaml` was only *checked* in preflight, never applied) — no route in or out, so `apt` DNS failed and "Wait for SSH" timed out at 10.0.1.51:22. The "Apply cloud-init settings" task now sets `net0` to `virtio,bridge={{ network_bridge }}` (+ optional `network_vlan_tag`) with `update_unsafe: true`, and also passes `nameservers`/`searchdomains` (new `forgejo_nameservers`/`forgejo_searchdomains` — required with a static `forgejo_ip_config`, which otherwise leaves the guest with no resolver) and `ciupgrade: false` (a first-boot dist-upgrade only slows boot and stalls it on any DNS hiccup; `forgejo_prereqs` does its own apt work). `proxmox_preflight` now hard-fails if `network_bridge` is unset/placeholder, or if a static IP is configured with no `forgejo_nameservers`.
- `README.md`: removed the last stale references to the retired `prepare_vm_template` role — the "Template prep" step under "What it does" (which also still said "Debian 12") and the `inventory/hosts.ini` `[proxmox_pve1]` SSH-access line in Prerequisites; the Preflight step now states the template is built out-of-band by `../Shared/Ansible/create-template-linux.yaml`. Also dropped a stale "cloud image URLs are pinned" limitation bullet.
- `README.md`/`docs/ANSIBLE_VAULT_GUIDE.md`/`inventory/group_vars/forgejo/vault.yaml.example`/`Install-Prerequisites.sh`: replaced every `ansible-vault create/encrypt --vault-id homelab@prompt ...` example with the plain form (no flag) — verified directly that with one identity configured in `vault_identity_list`, `--vault-id ...@prompt` was pure friction (forces retyping a password that's already in the configured file) rather than being required. Also fixed the multi-identity example in section 12, which used the wrong flag entirely (`--vault-id dc2@prompt` instead of `--encrypt-vault-id dc2`) — verified both behaviors directly rather than assuming.
- `deploy_forgejo.yaml`: the `prepare_vm_template` play unconditionally gathered facts on `proxmox_pve1`, which required a working SSH connection to the real Proxmox node even on the common no-op path where the template already exists (its own tasks correctly gate all SSH-requiring work behind an API check and never needed the connection in that case). Set `gather_facts: false` — nothing in the role uses gathered facts. Verified end-to-end against a real cluster: the play now completes with zero SSH connection attempts when the template already exists.
- `create_forgejo_vm`: the disk-resize task passed `forgejo_disk_size` (a bare number, documented in GB) straight to `community.proxmox.proxmox_disk`'s `size` parameter with no unit suffix — the underlying Proxmox resize API doesn't treat an unsuffixed value as GiB there, so it was interpreted as a tiny absolute size and failed with `shrinking disks is not supported` against any real template disk. Fixed by appending `G` explicitly (`"{{ forgejo_disk_size }}G"`).
- `forgejo_prereqs`: dropped `cache_valid_time: 3600` from the "Update apt cache" task — observed skipping the real `apt-get update` on a brand-new VM (likely trusting file mtimes from image build/cloud-init as "recent enough"), leaving even a base package like `git` unavailable to the very next task despite the VM having full, working internet/DNS access. This role only runs once per VM's life, so there's no real cost to always updating for real. Verified directly against a live VM: with the fix, cache update + package install both succeed.
- `forgejo_database`: the database-creation task hardcoded `lc_collate`/`lc_ctype` to `en_US.UTF-8`, which Debian's minimal cloud image never generates (`locale -a` on a real deployed VM showed only `C`/`C.utf8`/`POSIX`) — `CREATE DATABASE` failed outright. Switched to `C.UTF-8`, which is always present without installing/generating anything extra. Verified directly against the real Postgres instance.
- `forgejo_database`: fixed a typo (`insertBefore` → `insertbefore`, the actual `ansible.builtin.blockinfile` parameter name) in the pg_hba rule task. Verified end-to-end against a live VM: the rule is correctly written and, more importantly, a real password-authenticated TCP connection as the forgejo role succeeds — Debian's default `127.0.0.1` catch-all rule already permits the same access, so exact placement relative to it doesn't affect behavior.
- `forgejo_install`/vault secrets: `forgejo_secret_key`/`forgejo_internal_token`/`forgejo_jwt_secret` were documented and generated as `openssl rand -hex 32` — Forgejo's decoder requires URL-safe, **unpadded** base64 for these and rejects hex (and even standard padded base64) with `illegal base64 data`/`invalid base64 decoded length`, confirmed against a real crash-looping deploy. Also found and fixed a related gap: `LFS_START_SERVER = true` requires its own `LFS_JWT_SECRET`, which was never configured at all, so Forgejo tried to self-generate one and hit the systemd `ReadWritePaths` hardening (a real protection working correctly, not a bug). Added `forgejo_lfs_jwt_secret`/`vault_forgejo_lfs_jwt_secret` end-to-end (template, vars.yaml, vault.yaml.example, guide). Regenerated all four secrets in the correct format and verified the full chain live: `forgejo_prereqs` → `forgejo_install` → `forgejo_verify` all pass, and Forgejo actually serves `/api/healthz` successfully.
- `forgejo_prereqs`: pre-create `{{ forgejo_home_dir }}/.ansible/tmp` (owned by the forgejo system user) instead of letting Ansible create-and-hand-off `remote_tmp` on the fly the first time a task uses `become_user` to switch to that account — the on-the-fly path is a known-fragile handoff across some sudo configs and was surfacing its own warning in `forgejo_install`. Verified live: the warning is gone on a re-run.
